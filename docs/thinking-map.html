Outbound BDR Agent — Thinking Map

One campaign brief goes in. Nine specialist agents hand off to each other and produce a qualified account list, the people to contact, sourced research, and a written email per contact. Every gate below is a real branch in the code — including the ones that stop the pipeline rather than guess.

Step Decision Route Stop
Delegation — nine agents, one job each

The core decision: not one prompt that does everything. Each agent owns a single job, so a failure is attributable to a stage instead of degrading the whole answer.

Retrieval contract
The model is never allowed to write a URL
Search runs first. The model receives a numbered evidence list of pages we actually fetched and cites by index; we map indexes back to those URLs. A fabricated citation is not discouraged — it is unrepresentable.

Notes
Context
Depth over breadth. The brief rewards strategic insight, not volume, so the run qualifies a handful of accounts properly rather than listing fifty. Retrieval is keyless (Bing RSS + Wikipedia) so the system runs with no paid data vendor.
Edges
Contact discovery is the weak stage. Named ops/HSE leaders live on LinkedIn, behind auth, and corporate leadership pages are JS-rendered. The system refuses to invent a person, so it degrades to role-targeted and says so. 3 of 4 accounts returned thin English-language coverage and produced 0 claims.
Open
Next: put a licensed contact provider (Apollo / Cognism / Sales Navigator) behind A5 — the verifier gate downstream is unchanged, so nothing enters an email unsourced. Then Spanish/Portuguese query variants in A3, and paid provider tiers: both free tiers hit their daily token cap mid-run.
